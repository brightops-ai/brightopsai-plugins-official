# Analysis modes

The extraction is one thing; what you ask of it is another. The mode argument
keeps the expensive part reusable.

## `dream`

The question: **what should have been remembered, and was not?**

Produce, in `analysis.md`:

- Clusters of related episodes, grouped by what was being corrected — the file,
  the tool, the convention — never by how it was phrased
- For each cluster: what happened, how many times, across how many sessions
- What a memory or rule would need to say for it to stop recurring
- Whether it belongs in memory, in a path-scoped rule, or in an instruction file

Order by recurrence. Separate clusters of three or more across different
sessions (a pattern) from clusters of one (an observation). Say which is which;
a reader deciding what to write into memory needs to know how much evidence
stands behind each proposal.

## `time`

The question: **where did the time go?**

The same episodes read differently: `tool-failure` clusters become time lost to
a recurring problem, `interrupted` episodes become abandoned directions. Produce
a breakdown by project and by recurring failure, ordered by cost.

Nothing about memory is written or proposed in this mode.

## Adding a mode

A mode is a question asked of the digest, not new extraction. Add one when the
question is genuinely different — not when the same question wants a different
output format.

Give the mode a section here saying what question it asks, what it writes, and
what it deliberately does not do. A mode that quietly writes files another mode
owns will be found out by the reader who ran the wrong one.
