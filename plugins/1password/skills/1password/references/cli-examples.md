# op CLI examples (from op help)

Every example outside the last section keeps the secret value off the
terminal, off the command line and out of the work tree. Run them with shell
tracing off (SKILL.md, "Common operations").

## Sign in

Assign, check, then eval: a failed sign-in is reported, and the session token
`op signin` prints without app integration is never shown.

```bash
if s="$(op signin)"; then eval "$s"; else echo "op signin failed" >&2; fi; unset s
```

For one account of several, add
`--account <shorthand|signin-address|account-id|user-id>` to `op signin`, or
set `OP_ACCOUNT`.

## Read

```bash
set -o pipefail
op read op://<your-vault>/db/password | <command-that-reads-stdin>
```

```bash
if DB_PASSWORD="$(op read op://<your-vault>/db/password)"; then
  export DB_PASSWORD
else
  unset DB_PASSWORD
  echo "op read failed; DB_PASSWORD not exported" >&2
fi
```

## Secret-bearing files

When a consumer accepts a key or a rendered config only as a file, write it
to a private temporary directory outside every git work tree and remove it
afterwards. The subshell keeps `exit` and the cleanup trap local to the block:

```bash
(
  set +x
  umask 077
  SECRET_DIR="$(mktemp -d)" || exit 1
  [ -d "$SECRET_DIR" ] || exit 1
  trap 'rm -rf "$SECRET_DIR"' EXIT
  trap 'exit 1' INT TERM HUP
  if [ "$(git -C "$SECRET_DIR" rev-parse --is-inside-work-tree 2>/dev/null)" = true ]; then
    echo "refusing: $SECRET_DIR is inside a git work tree (check TMPDIR)" >&2
    exit 1
  fi
  op read --out-file "$SECRET_DIR/key.pem" op://<your-vault>/server/ssh/key.pem >/dev/null || exit 1
  <command> --key "$SECRET_DIR/key.pem"
)
```

- Allocation is checked before anything uses the path, so a failed `mktemp`
  cannot turn the target into `/key.pem`.
- The trap is installed before the secret is written and also runs on a
  failed read or an interrupt.
- `mktemp -d` can honour `TMPDIR` (GNU `mktemp` does); the work-tree check
  refuses a temporary directory that lands inside a repository.
- `umask 077`, the mode-700 directory and `--out-file` (owner-only by
  default) keep the file private.

For a rendered config, replace the `op read` line with
`op inject -i config.yml.tpl -o "$SECRET_DIR/config.yml" >/dev/null || exit 1`
and point the consumer at that file.

## Run

`./.env` and the exported variable hold `op://` references, not values.
`op run` resolves them for the subprocess only and masks them in its output.

- `export DB_PASSWORD="op://<your-vault>/db/password"`
- `op run -- <command>`
- `op run --env-file="./.env" -- <command>`

## Inject

```bash
set -o pipefail
op inject -i config.yml.tpl | <command-that-reads-config-on-stdin>
```

Never `-o config.yml` or any other relative path: in a repository that is the
work tree. For a file, see "Secret-bearing files".

## Create / store

The agent never receives the value (SKILL.md, "Store a new secret").

- Empty item for the user to fill in the 1Password app:
  `op item create --category=api-credential --title="Service Name" --vault="<your-vault>"`
- Value generated by 1Password, summary discarded:
  `op item create --category=password --title="Service Name" --vault="<your-vault>" --generate-password >/dev/null`
- Check that the item and field exist, by name:
  `if op read "op://<your-vault>/Service Name/password" | grep -q .; then echo present; else echo "missing or empty"; fi`

## For a human at a terminal only — never for an agent

Each command below prints a secret value to the terminal or takes one as
input. An agent must not run them, in a shell tool or in a tmux pane: the
value would enter the transcript. When the user asks to see or enter a value,
hand them the command to run in their own terminal.

- `op read op://<your-vault>/db/password`
- `op read "op://<your-vault>/db/one-time password?attribute=otp"`
- `op read "op://<your-vault>/ssh key/private key?ssh-format=openssh"`
- `op run --no-masking -- printenv DB_PASSWORD`
- `echo "db_password: {{ op://<your-vault>/db/password }}" | op inject`
- `op item create --category=api-credential --title="Service Name" --vault="<your-vault>" 'credential=<value>'`
  — the value lands in shell history and the process list; pasting it into
  the 1Password app avoids both
- `op account add` — prompts for the Secret Key and account password
